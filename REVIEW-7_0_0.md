# Review of PR #273: branch 7_0_0 into master

Reviewed at commit 8dfc1c8 (352 commits, 412 files, about 62,500 added lines including tests and data) against the final tree. A defect the branch introduced and fixed later is not listed. Skipped: tests/data/*.json, package-lock.json, binaries, features/*, store/images/*.

Method: nine area reviewers (service worker and messaging; TabManager, selection, search and keys; saved windows, storage, import and export; drag and drop; window naming, punycode, public suffix list and RTL; options, permissions and popup size; CSS; manifests, build, CSP and store text; test coverage), each reading the code path end to end and running the related tests or a node snippet, then three verifiers re-checking every finding against the final tree, re-running the snippets and judging severity. Nothing was run in a browser; claims about Chrome or Firefox behaviour that could not be executed are marked as such.

## Not findings

Things that looked suspicious and were checked end to end; all fine in the final tree.

Service worker and messaging
- All runtime, commands, tabs, windows, contextMenus, action and alarms listeners are registered synchronously at module top level; no lazily registered listener remains.
- `handleMessages` returns the dispatch promise (polyfill turns it into `return true` plus `sendResponse`), returns undefined for unknown commands, and turns a thrown handler into an undefined answer that every popup caller handles. Every `S.*` command the popup sends has a dispatch case.
- The worker version stamp is present in both bundles and matches the popup bundle per browser; a stale notice needs a rebuild without reload.
- Active-tab history survives worker suspension through storage.session; the `serialized()` queue in storage.ts is ordered, isolates rejections and removes the read-modify-write race (snippet-verified); no queued function re-enters it.
- `forgetWindowIds` runs before the first `cleanUp`; the hourly `cleanUp(true)` cannot drop an entry early. tabs.onRemoved and windows.onRemoved touch disjoint state.
- Restore geometry: unusable, NaN or string bounds fall back to browser placement; a saved window on a gone monitor is fitted into the popup's display; maximized windows are created normal then maximized and re-checked; a refused create falls back to 800x600 and a refused fallback becomes a popup error, not a blank popup.
- `loadApp` catches any boot rejection and retries up to ten times.
- Firefox: every API used exists at the 140 minimum; `chrome.system.display` and its permission check run only on non-Firefox branches in the worker (bundle verified) and are wrapped on the popup side.

TabManager, selection, search, keys
- No React error boundary, same as master; every render path traced guards its inputs.
- Every listener and timer added in componentDidMount is removed in componentWillUnmount; `unmounted` is set before the closing flushes.
- Selection ids of closed tabs are pruned in `update()` and filtered through `tabsbyid` before any worker message.
- User regex input is in try/catch with a literal fallback; case folding is applied to both sides.
- Keys in inputs: WindowOptions stops Enter and Escape; Ctrl+Backspace/Delete in the search box with text stay text editing; Ctrl+Z yields to text fields with content.
- Right-click, modifier click, range select and middle-click close keep master's branching exactly.
- Highlight Duplicates leaving stale `searchPicks` is harmless: every consumer ignores ids not in the selection.

Saved windows, storage, export
- Storage shape is unchanged from master (`storage.local.sessions = { [uuid]: ISavedSession }`); the branch adds optional `order` and `updated` and `tidyStored` never drops a key or an entry.
- Both manifests declare `unlimitedStorage`; `storage.sync` is unused; a refused `storage.local.set` on the saved-window path is handled by `SavedWrites.apply` (revert and re-read) and reported via `refusedText`.
- The 5.x migration, run against a fake profile: consolidated write before any remove, bad JSON left out, flags cleared only afterwards; a failed write removes nothing and the migration re-runs; idempotent.
- `sessionsUpgrade` through `readSettings`: 6.x false with no saved windows turns the feature on once; false next to saved windows stays off; legacy `dark: true` becomes "dark".
- Within a popup every saved-window change is queued and the closing flush writes from the copy; across two popups the last set wins as on master and `storage.onChanged` resyncs. The worker only reads `sessions`.
- Pending deletes find tabs by index and address and leave a window another popup or an import changed; an import flushes pending deletes first.
- Ids are v4 UUIDs; `JSON.parse` in both imports and `readBootCache` is caught; settings import validates type, choices, range and permission before writing.
- The restorable "Export Sessions" keeps full URLs on purpose and sits in a separate box from the debug export (finding 1).
- No URL or title reaches `console.log` in the popup; the restore diagnostic carries ids, names and geometry only.

Drag and drop
- `readTabDrag`, `decodeSaved`, `decodeIds`: JSON.parse guarded, every entry type-checked, duplicates dropped, `getData` throwing caught; a foreign page can only make the popup act on ids the popup already knows, and only on the user's own drop.
